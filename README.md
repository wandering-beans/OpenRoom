# OpenRoom

Lightroom Classicのような写真管理・編集アプリに向けて開発しています。既存の写真をコピーせずに管理するライブラリと、原本を変更せずに調整する現像機能を備えています。

## 画面と操作

提供されたLightroom Classicのライブラリ画面を基準に、黒いモジュールバー、左のナビゲーターとフォルダ階層、灰色の写真表示領域、表示ツールバー、下部のフィルムストリップを配置しました。右のメタデータパネルは、参照画像に合わせて初期状態で閉じています。アプリ名はOpenRoomです。白いOrと分光を使ったアイコンを採用し、ヘッダーとカタログの読み込み中に表示する起動画面に反映しています。

起動時はルーペで写真を1枚表示し、ナビゲーターとフィルムストリップの選択を連動させています。左のフォルダを選ぶと、配下の写真を件数付きで絞り込めます。フォルダの一覧と件数はカタログから取得し、画面を開くたびに保存先を走査する処理はありません。

フォルダ追加時は追加した読み込み元だけを走査し、絞り込みを解除してその写真を表示します。選択中の「再読み込み」も同じ読み込み元が対象です。「すべての写真」で再読み込みした場合は、登録済みの読み込み元をすべて走査します。

| 操作 | 動作 |
| --- | --- |
| G / E | ライブラリのグリッド / ルーペ表示 |
| C / N | ライブラリの比較 / 選別表示 |
| D | 現像を開く |
| Cmd+S / Ctrl+S | 現像設定を今すぐ保存 |
| Cmd+Z / Ctrl+Z | 現像設定を取り消す（数値入力中は入力欄の取り消し） |
| Space | グリッドとルーペの切り替え |
| ← / → | 前後の写真を選択 |
| 0〜5 | 未評価・星1〜5をカタログに保存 |
| P / X / U | 採用 / 除外 / フラグ解除を保存 |
| Cmd+F / Ctrl+F | 検索欄を開く |
| \ | ライブラリフィルターの表示切り替え |
| ナビゲーターの全体・100%・50% | 写真の表示倍率を変更 |
| 左右端の三角ボタン | サイドパネルを開閉 |
| 下端の三角ボタン | フィルムストリップを開閉 |

表示ツールバーの星評価とフィルムストリップの評価フィルターも利用できます。グリッドとフィルムストリップは表示範囲だけを描画し、200枚ずつ追加取得する方式です。

比較表示（C）は基準と候補の2枚を並べ、左右キーで基準を固定したまま候補を送ります。「入れ替え」で左右の役割を交換し、「候補を基準に」で基準を更新して次の候補へ進みます。倍率ボタン・ピンチ・ドラッグで拡大と移動を操作し、「拡大・移動を連動」で2枚を同じ倍率・位置で確認できます。

選別表示（N）は選択した写真を並べ、「候補から外す」で選択と表示から外します。原本やカタログの写真は削除しません。比較・選別中の評価・フラグ・ラベルは、白枠の写真1枚が対象です。写真の右クリックから、選択した写真を書き出せます。同じ写真の編集状態を比べるには、現像の変更前比較やスナップショット比較を使います。

ライブラリ上部には「テキスト・属性・メタデータ・なし」を配置しました。属性では星の以上・一致・以下、採用・除外・未設定、5色のカラーラベルを組み合わせて絞り込めます。メタデータは日付・カメラ・レンズ・ラベルの4列が初期表示です。列見出しからISO・絞り・焦点距離・形式へ変更でき、Cmd/Ctrl+クリックで同じ列の複数値を選べます。形式列は単一選択です。0.7.3では重複していた形式ボタンと拡張子メニューを削除し、形式の絞り込みをこの列に統一しました。列間はAND条件、同じ列の選択値はOR条件として扱います。

メタデータを開くと、選択したフォルダ配下の写真から撮影情報を順次読み込みます。フォルダを切り替えると前の読み込みを中止し、移動先を読み込みます。「すべての写真」ではカタログ全体が対象です。進捗表示と中止ボタンがあり、次回は保存済みの索引を利用します。索引の作成中は、未処理の写真がメタデータ条件に一致しないことがあります。除外は分類用のフラグで、原本を削除しません。

## 現像

右側をヒストグラム、編集ツール、基本補正、トーンカーブの順に整理し、プリセット・同期・比較・スナップショットを左へ移しました。カーブはクリックで点を追加し、ドラッグで入出力を調整します。数値入力、矢印キー、内部の点の削除にも対応します。チャンネルごとに最大32点を保存し、点間を滑らかにつなぎます。従来の5点カーブは、そのチャンネルを編集するまで従来の補間を保ちます。

現像を初めて開くと左パネルは閉じています。左端の三角ボタンからプリセットやヒストリーを開けます。開閉状態はライブラリと現像で別々に、アプリを終了するまで保持します。基本補正はホワイトバランス・階調・外観に分け、写真の下に変更前比較・取り消し・保存を配置しました。右下には「前の設定／リセット」を固定し、補正欄はその上でスクロールします。

現像タブの右パネルから、基本補正、RGB共通・チャンネル別のポイントトーンカーブ、8色のHSL、4領域のカラーグレーディング、シャープ・通常のノイズ低減、切り抜き・回転・反転・手動の遠近と歪曲補正、周辺光量・粒子を調整できます。切り抜きは画像上のドラッグと数値入力に対応し、縦横比の固定、枠の移動、右下の角でのサイズ変更、水平線の指定、変形後の余白の除去ができます。スライダーのダブルクリックで、その項目を初期値へ戻せます。

部分補正はブラシ、線形・円形グラデーション、色域・輝度域を使い、追加・減算・共通部分・反転を組み合わせます。露光量、色、コントラスト、質感、シャープとノイズ低減を局所的に調整できます。マスクは変形後・切り抜き前の座標に固定されるため、幾何変形を先に行ってください。

ユーザープリセットの保存・名前変更・削除とJSONの読み書き、補正グループを選んだコピー・貼り付け、複数写真への同期・自動同期、前の写真の設定の適用に対応します。Cmd/Ctrl+クリックで追加選択、Shift+クリックで範囲選択します。取り消し・やり直し、リセット、変更前比較も利用できます。現像設定は操作が600ms止まるとカタログへ自動保存します。スライダー操作中は保存を待機し、保存では画像を再生成しません。ライブラリ・フィルムストリップ用の画像は、別の写真に移った後、現像操作が止まってから更新します。更新中も以前の画像を表示し、未完了の更新はカタログに残して次回の写真切り替えで再開します。「今すぐ保存」でも保存できます。写真・モジュールの切り替えと通常の終了では、最新の設定を保存してから移動します。保存に失敗した場合は編集内容を画面に保持し、移動を止めて再試行を案内します。

現像画面の「ヒストリー」には現在の状態と直近10回分を保存します。連続したスライダードラッグは1操作として扱い、Cmd/Ctrl+Zで最大10回取り消せます。保存後や写真の再表示・アプリ再起動後も取り消せます。やり直しは開いている現像画面内で保持し、新しい編集で破棄します。10回より古い通常履歴は残しません。名前付きスナップショットとプリセットはこの制限の対象外です。強制終了などで自動保存が完了しなかった直近の変更は復元できません。履歴の名前変更、名前付きスナップショットの保存・復元、選んだ履歴やスナップショットとの左右・分割比較にも対応します。タグ・メモの編集は従来どおり手動保存です。

書き出しはライブラリの写真一覧、ライブラリ・現像の下部フィルムストリップで写真を選び、右クリックの「書き出し」から行います。画質、容量制限、保存先、命名規則、形式と長辺の縮小サイズを指定できます。JPEG品質は1〜100、PNG/TIFFは16bitで、sRGBのICCプロファイルを付けます。単体・一括とも元の解像度から処理し、原本と既存の出力を上書きしません。EXIF・GPSなど元画像のメタデータは転記しません。現在の書き出しはSDRです。一括出力では進捗・中止・写真ごとの失敗を表示します。ハードリンク非対応の保存先では、上書きしない新規ファイルへのコピーに切り替えます。

現像処理は`crates/develop-core`に分離しました。macOSではRawTherapee 5.13のrtengineがRAWデコード・カメラ色変換・WB・全体のノイズ低減とシャープ処理を担当し、C++側の線形露光ゲインとRust側の残りの補正を組み合わせます。RawTherapeeの画面は組み込みません。Windows/Linuxは従来のRust経路を使います。作業画像は32bit浮動小数点で保持します。384px・1,600px・原寸など、要求した表示サイズごとに作業画像をキャッシュし、通常の操作はメモリ上の画像を再利用します。ICCとHEIF/AVIFのNCLX色情報を読み、拡張線形sRGBへの変換で広色域と高輝度の値を保持します。10/12bitのSDR HEIF/AVIF、浮動小数点TIFF、16/32bitのRGB・グレースケールPSD/PSBの保存済み合成画像を、8bitへ丸めず現像します。色情報がない通常画像はsRGB、32bit浮動小数点TIFF・PSDは線形sRGBとして扱います。PQ/HLGのHDR HEIF/AVIFは未対応のため、誤ったSDR表示をせずエラーを表示します。入力上限は64MP・1GiBで、RAW対応はカメラと圧縮方式に依存します。

RAWの色温度は2,000〜60,000Kで指定でき、未調整時と「撮影時」ボタンでは撮影時WBを使います。旧形式の相対WBは開いただけでは書き換えず、K入力時に置き換えます。JPEG等も同じ2,000〜60,000Kで調整できます。macOSではメーカー固有のメタデータから有効な撮影時K値を取得し、補正なしの基準にします。取得できない場合は「推定基準6,504K」と表示します。これはD65を仮定した基準で、撮影時のK値を画像から逆算した値ではありません。「撮影時」で原本の色に戻ります。保存済みのK調整は当時の基準を維持します。従来のRust経路はLightroomとの実画像比較で校正しましたが、rtengine経路では色や質感が変わります。Adobeの画像に応じた階調調整とは差が残り、同じ設定値での完全一致には達していません。保存値と履歴は維持しますが、既存編集も新しい処理で表示・出力されるため見た目が変わる場合があります。AI補正、修復・生成削除、自動レンズプロファイル、色収差、HDR、ソフト校正などは後続です。

macOSのRAWは、撮影時WBとカメラ色変換に加え、RAW内の撮影時JPEGを参照して初期階調を合わせます。rtengineの既存処理で階調曲線を求め、セッション内で再利用します。初回解析には追加の時間がかかります。参照JPEGを利用できない場合は従来の標準階調へ戻ります。ライブラリ・現像・書き出しには同じ階調を適用し、JPEG等には重ねません。保存済みのRAW編集も新しい階調で表示・出力されるため、見た目が変わる場合があります。メーカー固有の色相や撮影スタイルの完全再現には未対応です。

処理分担の点検で、JPEG等の校正済み階調とDCPの基準露光補正の抜け、RAW縮小表示のシャープ半径を修正しました。RAW以外の露光・WBはRustが担当し、全体のシャープ・ノイズ低減はrtengineで一度適用します。

現像プレビューはスライダー操作中も通常表示の1600pxを維持し、原寸表示を選んでいる場合は原寸のまま更新します。次の描画が完了するまでは直前の画像を表示します。macOSのRAW現像ではハイライトの色復元を有効にし、白飛び部分が紫色になる問題を修正しました。

LRCの実出力との比較で、正の黒レベルと複数の階調補正を併用した際の明暗逆転を修正しました。連続入力中の不要な描画中断と操作終了時の重複描画も抑え、色温度スライダーを対数配置に変更しています。

画素変換を並列化し、シャープ調整ではノイズ低減の計算結果を再利用します。画像の縮小や補正の省略による高速化は行いません。

## 環境設定と言語

環境設定はアプリメニューから開きます。「言語 / Language」で日本語とEnglishを選択できます。言語の変更前に編集内容を保存して画面を再読み込みします。保存に失敗した場合は切り替えを止めます。言語設定はカタログと別に保存し、写真名・タグ・メモ・独自のプリセット名は変更しません。

左のカタログ欄には現在のカタログと「すべての写真」を表示します。「カタログを管理」を開くと、既存カタログを開く、新規作成、保存場所の表示、コピー保存ができます。

## AI連携（MCP）

起動中のOpenRoomを、同じPCのMCPクライアントから操作できます。macOSの「OpenRoom → 環境設定…」（⌘,）を開き、AI連携を有効にして「設定を適用」を押します。初期状態は無効です。接続方式はStreamable HTTP、標準URLは`http://127.0.0.1:39127/mcp`です。クライアントには、このURLと`Authorization: Bearer <設定画面でコピーしたトークン>`を指定してください。stdioとOAuthには対応していません。

有効・無効とポートはアプリ設定に、トークンはOSの資格情報ストアに保存します。次回は画面とカタログの準備後に自動起動します。ポートの競合や資格情報ストアの失敗は設定画面に表示し、接続の受付を始めません。LinuxではSecret Serviceが利用できるデスクトップ環境が必要です。トークンはカタログのコピーに含めません。設定画面の「再発行」で旧トークンを無効にできます。無効化・終了・カタログの再起動では受付を止め、進行中のMCPジョブを中止します。

接続すると、開いているカタログへの保存・書き出しを確認なしで実行できます。localhostだけで待ち受け、Bearer認証とHost・Originを検証します。原本の変更・削除、既存ファイルの上書き、カタログの作成・切り替えを行うツールは公開していません。

| 用途 | ツール |
| --- | --- |
| 状態・画面 | `get_app_state`、`select_photos`、`set_view` |
| 検索・詳細 | `list_roots`、`list_folders`、`search_photos`、`count_photos`、`get_photo`、`get_metadata`、`get_metadata_facets` |
| 取り込み | `add_root`、`start_scan`、`start_metadata_index` |
| 整理 | `update_photo_attributes`、`update_annotations` |
| 現像 | `get_develop_settings`、`preview_photo`、`update_develop_settings` |
| プリセット・履歴 | `list_presets`、`save_preset`、`apply_preset`、`list_develop_history`、`restore_develop_history` |
| 書き出し・進捗 | `start_export`、`get_job`、`cancel_job` |

入力スキーマと説明は`tools/list`で取得できます。検索は1ページ最大200枚で、続きは同じ`query`と返された`next`を`cursor`として渡します。`select_photos`は最大200個のIDを受け取り、読み込み済みページの外にある写真も「AI選択」として表示します。先頭のIDが主選択です。画面の「絞り込みを解除」で通常の一覧へ戻せます。`set_view`は`grid`・`loupe`・`compare`・`survey`・`develop`に対応します。

たとえば、`search_photos`で探し、`preview_photo`の画像を確認してから、`select_photos`、`update_annotations`、`update_develop_settings`、`start_export`の順に操作できます。現像更新では、直前の`get_develop_settings`から得た`revision`を`expected_revision`に指定し、`patch`へ変更する項目だけを渡します。競合時は保存しません。プリセット適用と履歴復元にも現在のrevisionが必要で、どちらも新しい履歴を残します。

読み取りは保存済みデータが対象です。現像の`patch`と評価・タグ・メモの更新では、省略した項目を保持します。配列はフィールド全体の置換です。`preview_photo`に渡す一時的な`patch`は保存せず、JPEGをMCPの画像コンテンツとして返します。`get_app_state`では選択・表示・検索条件と未保存状態も取得できます。

変更と画面操作は直列に処理し、実行前に現像の自動保存を完了させます。未保存のタグ・メモ、保存失敗、モーダル表示中は内容を保持してエラーを返します。画面要求は30秒以内に実行を開始しなければ失効します。変更の保存後に画面更新だけが失敗した場合は、結果に`ui_updated: false`と`ui_error`を返します。応答を失った場合は保存済み状態を確認し、同じ変更を無条件に再送しないでください。

走査・メタデータ索引・一括書き出しはジョブIDを返します。`get_job`で完了まで確認し、結果の写真ごとのエラーも確認してください。索引作成は`query`のルート・フォルダ範囲が対象で、他の絞り込み条件は使いません。書き出しは開始時に対象と現像設定を固定し、指定した既存の絶対パスのディレクトリへ`<元の名前>-<ID>-edited.<拡張子>`で保存します。同名ファイルがあれば、その写真は失敗として返します。中止までに保存した編集や出力は残ります。ジョブの記録は起動中に最大100件保持します。

MCPの通信には[公式Rust SDK rmcp 3.6.0](https://github.com/modelcontextprotocol/rust-sdk/releases/tag/rmcp-v3.6.0)を使っています。

## カタログと付属プレビュー

写真の参照先、評価、タグ、メモ、現像設定と編集履歴を1つのSQLiteカタログで管理します。標準カタログは`catalog.db`です。現像設定は初期値と異なる項目だけを保存し、4KiB以上の設定・履歴・プリセット・スナップショットは圧縮します。原本は別に保管し、表示や編集で書き換えません。スキーマ9で履歴を制限する前に、既存DBの隣に`.before-history-limit.openroom`で終わる全履歴入りの復旧用コピーを一度作成します。このコピーは自動削除しません。スキーマ8以前からの移行では、従来の`.before-previews.openroom`も作成します。

初回取り込み時に、選択していない写真も含めて長辺1600px・384pxのプレビューを生成します。保存形式はsRGB・8bitのAVIFで、品質値は大きな画像65・一覧55です。AV1エンコーダーまたは画面側のAVIF対応がない環境ではJPEGへ切り替えます。既存カタログの未生成分は起動後に補完し、中断した処理は保存済みの分を再利用して再開します。生成済み写真は取り込み完了を待たずに閲覧できます。

保存先はカタログ名に`.previews`を付けた付属フォルダです。例えば`catalog.db`には`catalog.db.previews`が対応します。DBとこのフォルダはローカルSSDへ置き、原本だけをNASに置けます。ライブラリは保存済み画像を先に表示し、原本の更新確認は後から行います。拡大やピンチ操作でもライブラリの表示元はプレビューのままです。現像画面では原本をデコードし、現在の編集設定で高画質表示します。編集保存では画像を再生成せず、別の写真への移動後に更新します。現像からライブラリへ戻るときも、設定を保存して対象写真のプレビューを更新します。

プレビューは7.5GB、現像用作業キャッシュは1GBを上限とし、DBとログを含む通常の保存は9.5GB以内に収まるか事前確認します。残り0.5GBは置換などの余裕です。一括生成で保存枠が不足したら停止してカタログ分割を案内します。閲覧時の再生成では古い大きなプレビューを整理できます。整理した画像を一括補完で作り直し続けることはありません。原本や編集履歴は整理対象にしません。

左パネルの「カタログ」から「保存場所を開く」と「カタログのコピーを保存…」を使えます。コピーは最新の設定・評価・履歴を含む`.openroom`ファイルと、対応する`.previews`フォルダです。原本と現像用作業キャッシュはコピーしません。手動でカタログを移動する際も、DBと付属フォルダを一緒に移動してください。既存の保存先は上書きしません。CLIの`backup`はDBのスナップショットだけを作成します。

動作中は高速な書き込みと障害復旧のため、SQLiteの一時的な`-wal`・`-shm`ファイルが付く場合があります。バックアップにはアプリのコピー機能を使ってください。「カタログを開く…」から`.openroom`や既存のOpenRoomの`.db`を選び、「新規カタログ…」で空のカタログを作れます。保存後にアプリが再起動し、選択先を開きます。次回の起動でも選択を保持します。コピーしたカタログを開けば、その時点の履歴と設定から再開できます。元の写真への参照先は維持されます。選択先が見つからない場合は通知して標準カタログを開きます。Lightroomカタログの取り込みは引き続き保留です。

## 現在の機能

写真フォルダの登録と差分読み込み、日本語の部分一致検索、形式・拡張子・並び順による絞り込みに対応します。サムネイル一覧は表示範囲だけを描画し、個別プレビューでは前後の写真への移動、拡大・縮小、フィット表示を使えます。

タグ・評価・メモの保存先はSQLiteのカタログです。EXIFから取得できる撮影日時、カメラ、レンズ、ISO、絞り、シャッター速度、焦点距離、GPSなどを表示します。写真の原本や原本のEXIFを書き換える処理はありません。

対応拡張子は29種類です。

| 分類 | 拡張子 |
| --- | --- |
| RAW | dng, cr2, cr3, crw, arw, sr2, srf, raf, nef, nrw, rw2, orf, pef, rwl, srw, 3fr, fff, iiq |
| JPEG | jpg, jpeg |
| HEIF | heic, heif, hif |
| その他の写真形式 | png, tif, tiff, avif |
| Photoshop連携用 | psd, psb |

NikonのNEF/NRW、PanasonicのRW2、OM／OlympusのORF、PentaxのPEF、LeicaのRWL、SamsungのSRW、Hasselbladの3FR/FFF、Phase OneのIIQを追加しました。

RAWの対応可否はカメラと圧縮方式に依存します。SigmaのX3Fと旧型Panasonic／Leicaの拡張子RAWは今回の対応に含みません。TIFFは先頭画像、PSD/PSBは保存済み合成画像を表示します。レイヤー編集は行いません。ライブラリのプレビューは8bit SDR・長辺最大1,600pxで、100%表示もこの画像のピクセルが基準です。「現像で原本を表示」から原本由来の表示へ移り、現像の「原寸表示」で原本の解像度を確認できます。原本を参照できない状態では保存プレビューを閲覧できますが、現像の読み込みと書き出しは原本の接続が必要です。

## 対象外の形式

PDF・SVG・GIF・BMP・WebP・HDR/EXRの索引作成と表示、PDFのページ移動、RAWのメーカー別フィルターを削除しました。RAWのメーカー・形式は拡張子で絞り込めます。SVG描画ライブラリと不要な画像デコーダー設定、専用の描画処理・テストも削除しています。

既存カタログにある対象外形式のレコードやタグ・評価・メモは保持したまま、検索・件数・一覧から除外する仕様です。対象外形式のプレビューも拒否します。原本は削除しません。カタログのバックアップ、整合性検査、走査の中止、未保存の編集内容の保護は維持しています。

## 開発・起動

Rust stable、Node.js 22.12以上と対象OSのビルド環境が必要です。デスクトップはTauri 2＋React＋TypeScript＋Viteです。ライブラリの未編集プレビューはmacOSでSwiftとImageIO/Core Imageを使用します。macOSの現像はrtengineとRustの組み合わせで、RAWには固定したrtengineを使います。Windows/LinuxのRAWは従来どおりrawler、HEIF/AVIFは全OSでlibheifを使います。

フロントエンドのソースは`desktop/ui/`、Viteの生成物は`desktop/ui-dist/`、Rustのバックエンドは`desktop/src/`に分離しています。フロントからのネイティブ呼び出しは`desktop/ui/backend.ts`を通します。フロント全体をTypeScript／TSXで記述し、厳格な型チェックを行います。写真一覧・現像操作・履歴・マスク・比較・設定・書き出しはReactで描画し、保存や画像の位置計算は型付きコントローラーが扱います。Rustのコマンド、カタログ形式、画像処理は変更していません。

依存の導入は`npm ci --prefix desktop`、型チェックとフロントのビルドは`npm --prefix desktop run build`で実行します。RustのcargoがPATH上で使える環境では、`npm --prefix desktop run tauri -- dev`でTauriとViteを起動できます。Vite単独のプレビューにはTauriのネイティブ機能はありません。

Cargoの`custom-protocol`機能は配布時だけ有効にします。Tauri CLIのbuildとmacOSのビルドスクリプトがこれを設定し、開発時は`devUrl`のViteへ接続します。Cargoから直接配布用バイナリを作る場合は`--features custom-protocol`が必要です。

macOSのビルドは一時フォルダで署名検証まで済ませてから`dist/OpenRoom.app`を交換します。配置先のアプリや画像処理ワーカーが動いている場合は、上書きせずエラーで終了します。アプリを通常終了してから再実行してください。

macOSのビルドにはCommand Line Toolsと次の依存が必要です。

```sh
brew install libheif pkgconf cmake ninja gtkmm3 fftw libiptcdata lensfun exiv2 little-cms2 libomp librsvg fmt libraw
npm ci --prefix desktop
./scripts/build-desktop.sh
open dist/OpenRoom.app
```

初回ビルドでは`native/rtengine/source.json`で固定したソースを`.tools/rtengine/`へ取得し、パッチを適用してCMakeでビルドします。アプリにはエンジン、カメラデータ、プロファイル、ライセンス本文とパッチを同梱します。

`dist/OpenRoom.app`はローカル開発用のad-hoc署名です。公開配布用の署名・公証は行っていません。最低OSはビルドに使うlibheifなどの依存ライブラリにも依存します。

`./scripts/cargo-local.sh`はPATHのcargoを使用し、なければ一時領域のRustツールチェーンを探します。一時領域が消えた場合はRustを導入し直してください。

Windows/Linuxでも共通の検索・カタログ・描画処理を使用します。パッケージ作成には各OSのTauriビルド環境とlibheifが必要です。Linuxはlibheif-devとHEVC/AV1デコーダー、Windowsはvcpkgのlibheifを使用します。他OSでの起動は今回未確認です。

## データと検証

アプリの識別子は既存の`local.advanced-explorer.desktop`を維持します。macOSの標準カタログは`~/Library/Application Support/local.advanced-explorer.desktop/catalog.db`、プレビューはカタログに隣接する`catalog.db.previews/`、現像用作業キャッシュはその中の`working/`です。テスト用カタログは`AE_DATA_DIR`で分離できます。

隠しファイル、シンボリックリンク、アプリや写真ライブラリの内部は走査しません。アクセスできないルートを空として扱わず、タグやメモを保護します。カタログ保守用CLIにはバックアップと整合性検査を残しています。

```sh
npm ci --prefix desktop
npm --prefix desktop run build
npm --prefix desktop run test:unit
./scripts/cargo-local.sh test --locked
./scripts/cargo-local.sh test --manifest-path crates/media-core/Cargo.toml --locked
./scripts/cargo-local.sh test --manifest-path crates/develop-core/Cargo.toml --locked
./scripts/cargo-local.sh test --manifest-path desktop/Cargo.toml --locked
./scripts/cargo-local.sh clippy --locked --all-targets -- -D warnings
./scripts/cargo-local.sh clippy --manifest-path crates/media-core/Cargo.toml --locked --all-targets -- -D warnings
./scripts/cargo-local.sh clippy --manifest-path crates/develop-core/Cargo.toml --locked --all-targets -- -D warnings
./scripts/cargo-local.sh clippy --manifest-path desktop/Cargo.toml --locked --all-targets -- -D warnings
node scripts/test-desktop-ui.cjs
```

画面テストはTauriが同梱する`desktop/ui-dist/`を使います。Playwrightはnpm依存に含まれ、Chromiumは`desktop/`で`npx playwright install chromium`を実行して導入します。独自のChromium実行ファイルは`AE_CHROMIUM_EXECUTABLE`で指定できます。`npm --prefix desktop run test:ui`は単体テストとフロントのビルドを済ませてから画面テストを実行します。画面テストはTauri呼び出しを模擬するため、デコーダーやネイティブアプリの動作確認とは別です。実RAW/HEIFサンプルを使うテストは`AE_RAW_ASSETS`を指定して実行します。

依存ライブラリの出典と配布時の注意は[THIRD_PARTY.md](THIRD_PARTY.md)を参照してください。

0.5.1では現像のディテール処理を並列化し、保存後のサムネイル競合と破損キャッシュの復旧を修正しました。

## 配布時の個人データ保護

GitHubには監査済みのソースと必要な素材だけを含めます。写真原本、カタログ、プレビュー、編集履歴、認証情報、ローカルの調査記録と旧Git履歴は含めません。RAW検証用の写真はリポジトリに同梱せず、`reports/raw-heif-samples.json`に固定した公開サンプルを必要時に取得します。同梱テスト画像の出典は[fixtureの説明](crates/media-core/tests/fixtures/README.md)に記載しています。

共有前に`python3 scripts/test-privacy-check.py`と`python3 scripts/privacy-check.py --tracked`を実行してください。配布アプリは`python3 scripts/privacy-check.py dist/OpenRoom.app`でも確認できます。この検査はローカルパスや既知の秘密情報の形式を検出しますが、画像内の個人情報などを自動判定するものではありません。新しい画像やアーカイブを追加する場合は内容とメタデータも確認してください。

開発フォルダ全体をZIPにすると、Gitの除外設定に関係なくローカルデータが入ります。ソースの配布には監査済みコミットの`git archive`、アプリの配布には`dist/OpenRoom.app`だけを使用してください。アプリを起動すると作成される利用者のカタログとキャッシュは、配布ファイルとは別に保存されます。
